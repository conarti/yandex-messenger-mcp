## 🚨 Главный вывод: таблицы `int → emoji` не существует. Ни в бандле, ни на сервере.

Вопрос спайка был поставлен так, как будто где-то лежит `{1:"👍", 2:"👎"}`. **Её нет, и это не пробел
выемки — её нет by design.** Яндекс не рендерит реакции Unicode-эмодзи. Реакция — это **PNG-артворк,
который отдаёт сервер по id**:

```
https://files.messenger.yandex.net/reactions/{type}/{size}
```

`ui.chunk.js`, компонент реакции (вербатим, единственное место отрисовки):

```js
o.createElement("img",{src:ze.Z.get(u?"reactionWithVersionUrl":"reactionUrl",{type:t,size:"small",version:u}),
  className:je("icon"),"data-context-menu-disabled":!0,"data-test-tag":(0,te.w)("reaction-image")})
```

Шаблон — не в бандле, а в серверном HTML страницы:
`"reactionUrl":"https://{filePublicHost}/reactions/{type}/{size}"` (`filePublicHost` = `files.messenger.yandex.net`).

Следствия, которые надо принять в v2:
- **эмодзи-литералов в бандле нет вообще** — греп по 👍👎❤️🔥😁😢 по всем 15 чанкам даёт **0 совпадений**;
- единственный чанк с эмодзи (`emojis.chunk.js`, лениво грузится) — это пикер **редактора сообщений**
  (9 паков, пары `["😃",":smiley:"]`), к реакциям отношения **не имеет**;
- **колонка `emoji` в нашей карте — НАША аппроксимация артворка**, а не то, что отдаёт сервер.
  Авторитетны `name` (имя ассета с сервера) и сам артворк. Для текстового MCP-вывода аппроксимация —
  единственный вариант, но выдавать её за «эмодзи от Яндекса» нельзя.

## Набор пикера — из конфига, не из бандла

Бандл несёт только **пустую заглушку**: `"reactions_enabled":false,"reactions_by_namespace":{}`.
Живой набор приходит с `https://tools.messenger.yandex.net/config.json`.

Селектор набора (`app.js`, модуль `66478`, экспорт `Mp`, вербатим):

- ключ — namespace чата: `private` / `<ns>` / `default`; `g` добавляет суффикс `_team` для Я.Team;
- `extended_*` включается фича-флагом (`web_enable_extended_reactions_picker`), иначе базовый набор;
- сезонные ключи (`__ny_*`, `__march8_*`, `__sept3_*`) в дефолте не активны — их подменяют вручную к дате.

## 🚨 Тип НЕ валидируется сервером. Набор НЕ ограничен.

Ключевая находка, ломающая посылку «набор небольшой, карта будет полной». Полной она быть **не может**:

| `push({ClientMessage:{Reaction:{Type}}}, Action:2)` | commit | `list_reactions` | `MyReactions` |
|---|---|---|---|
| `128077` (legacy 👍, вне пикера) | `Status:1` | `[128077]` | `[128077]` |
| `129393` (legacy 🥱, вне пикера) | `Status:1` | `[129393]` | `[129393]` |
| `100113` (есть ассет, нет в базовом пикере) | `Status:1` | `[100113]` | `[100113]` |
| **`1`** (ассета нет, 404) | `Status:1` | `[1]` | `[1]` |
| **`999999`** (ассета нет, 404) | `Status:1` | `[999999]` | `[999999]` |

**Сервер принимает любой int и отдаёт его обратно дословно.** Пикер — это витрина UI, а не контракт.
Это же объясняет спайк 4: `Type:1` тогда прошёл (`Status:1`) не потому, что `1` — валидная реакция,
а потому, что валидации нет вовсе. **`1` — мусор, а не 👍.** Запись `1 → 👍` в карту вносить нельзя.

**Что делает официальный веб с неизвестным типом** (поставили `999999`, открыли UI):
запрос `reactions/999999/small` → **404**, `naturalWidth: 0` — **битая картинка**. Фолбэка нет
даже у Яндекса. Значит и мы не обязаны притворяться, что знаем ответ.

## Меню эмодзи в инпуте — это ТЕКСТОВЫЙ композер. К реакциям отношения не имеет.

Проверено по наводке пользователя. **Гипотеза координатора верна, карту не расширяем.**

Панель по кнопке 😊 в инпуте — вкладки **Emoji | Stickers | Images** + категории (смайлы, животные,
еда, спорт, транспорт, объекты, символы, флаги). Привязана к **полю ввода**, а не к сообщению.

Решающее отличие от пикера реакций — в DOM, и оно бинарное:

| | пикер **реакций** | меню эмодзи в **инпуте** |
|---|---|---|
| `<img>` в панели | **все элементы** | **0** |
| текстовых Unicode-узлов | **0** | **все** (`innerHTML === "😃"`) |
| источник набора | `config.json` по namespace | чанк `610 emojis.chunk.js`, 9 паков |
| что делает клик | `sendReaction(chatId, ts, type)` | вставляет символ в `contenteditable` |

**Доказано живьём:** клик по 😃 в панели → в поле ввода появился **литерал `😃`**; узел панели —
`<div class="ui-pressable yamb-emoji__item emoji">😃</div>`, без всякого `img`. Реакция при этом
не ставится вовсе — панель к сообщению не привязана.

Эмодзи отсюда уходит **обычным символом внутри `Text.MessageText`**. Это согласуется со спайком 2
(строка возвращается байт-в-байт). **Маппинг `int` тут не нужен и не применим:** эмодзи в тексте —
это просто символы в строке, а не реакции.

### Поставить РЕАКЦИЮ произвольным эмодзи из UI нельзя

Проверена и альтернатива — «расширенный» пикер реакций (шеврон `.yamb-reactions-picker__expand-button`):

- развёрнутый пикер отдал **ровно 29 `<img>`**;
- типы **посимвольно совпали с `extended_reactions_by_namespace.private` и в том же порядке**;
- **текстовых эмодзи — 0**, **полей поиска/ввода — 0**.

То есть UI-пути поставить реакцию произвольным эмодзи **не существует**: набор закрыт конфигом.

⚠️ **Закрытость — свойство UI, а не сервера.** Сервер по-прежнему съест любой int (`999999` → `Status:1`).
Пункт «что делать с неизвестным int» остаётся в силе в полном объёме.

### Что это говорит про 10 legacy-записей с `id == кодпоинт`

Гипотезу «legacy — это следы механики произвольных эмодзи-реакций» **проверка не подтверждает**.
Свип по ~50 популярным кодпоинтам дал 404 на всех, кроме тех же десяти. Если бы механика
«реакция любым эмодзи» существовала хоть когда-то, ассеты нашлись бы шире десяти.
Правдоподобнее: старый **фиксированный** набор v1 из 10 реакций, чьи id просто выбрали равными
кодпоинтам изображаемых эмодзи. Это **реконструкция мотива, а не доказанный факт** — прямых
свидетельств происхождения id у нас нет.

## Что делать с неизвестным int — предложение

Официальный клиент падает в битую картинку. Нам нужно лучше: **не врать и не терять данные**.

```jsonc
// известный
{ "type": 100102, "name": "like-ext", "emoji": "👍", "count": 3 }
// неизвестный - НЕ выдумываем эмодзи
{ "type": 999999, "name": null, "emoji": null, "unknown": true, "count": 1 }
```

Правила:
1. **Карта — lookup с фолбэком, а не `switch`, который бросает.** Неизвестный тип — штатный сценарий
   (доказано: сервер принимает любой int), а не баг. Ронять `get_message` из-за реакции нельзя.
2. **`type` отдавать ВСЕГДА**, даже когда `name`/`emoji` известны. Это единственное, что реально пришло
   с провода; всё остальное — наша интерпретация. Пользователь должен иметь возможность отличить.
3. **Не подставлять `chr(type)`** как «эмодзи по кодпоинту». Для `100102` это `𘜆` (тангутский иероглиф),
   для `999999` — вообще не символ. Правило кодпоинта верно ровно для 10 legacy-записей и больше нигде.
4. **Текстовый фолбэк** — `⬜ (реакция 999999)` либо просто `999999`; выбор за форматтером, но
   молча глотать реакцию нельзя: `Reactions[].Count` тогда не сойдётся с суммой показанного.
5. **На запись (`set_reaction`)** — валидировать по карте **до** отправки. Сервер не защитит:
   он молча запишет мусор, и его увидят все участники чата. Это единственное место, где строгость нужна.
6. **Карта — данные, не код.** `reaction-map.json` перегенерируется свипом по `/reactions/{type}/small`
   (301 vs 404 + имя из `Location`) — процедура воспроизводима и не требует бандла.

## Поправки в `yandex-messenger-api-research.md`

1. **§17.12**: `Type:1` в свипе прошёл **не потому, что `1` = 👍**, а потому, что **сервер не валидирует
   `Type` вовсе** (`999999` → `Status:1`). Формулировку «`1` → `Status:1`» надо снабдить этим.
2. **§17.12 / §14.3**: **`Limit` в `list_reactions` обязателен.** Живьём `{ChatId, Timestamp}` без `Limit`
   → `BACKEND_CALL_ERROR(2)`; `{ChatId, Timestamp, Limit:50}` → OK. Спайк 4 этого не заметил.
   Аналогично `{ChatId, Timestamp, Mode:1}` без `Limit` падает — то есть «`Mode:3` → ошибка» из спайка 4
   стоит перепроверить с `Limit`.
3. **§9.3**: `Reaction` уходит **внутри `ClientMessage`**, полным конвертом `buildPushParams`
   (`ClientTransportId` + `UserAgent` + `Meta.Origin` + `ClientSupportedFeatures`). Плоский
   `push({Reaction:{...}})` даёт `Status:4 NO_SUCH_CHAT` — ложный след, легко принять за неверный `ChatId`.
4. **Новый раздел «Реакции»**: `Type` — не эмодзи и не кодпоинт, а id ассета;
   URL `https://files.messenger.yandex.net/reactions/{type}/{size}`; набор пикера — из
   `https://tools.messenger.yandex.net/config.json` по namespace.
5. **§Приложение**: `ListReactionsMode` из бандла — `{ONLY_REACTIONS:0, ONLY_READ_TIMESTAMPS:1, ALL:2}`.
   ⚠️ Имя `ALL:2` **врёт**: живьём `Mode:2` отдал только `UserReactions` (спайк 4). Верить наблюдению.
6. **§Приложение**: хеш бандла `0x421b6bd` подтверждён (не менялся); чанк `610:"emojis"` — пикер
   **редактора**, не реакций.
