## 🚨 РЕАЛЬНАЯ ФОРМА ГОЛОСА (unblock AC-29 v2 — чинит `buildVoteMutation`)

Клик по варианту + "Проголосовать" в существующем опросе → **`Status:1` FULLY_COMMITTED**.

```jsonc
// method: "push"   (тот же транспорт, что и Reaction)
{
  "ClientMessage": {
    "Vote": {
      "ChatId":   "0/0/<chat-uuid>",
      "Timestamp": 1700000000000000,   // мкс, = Timestamp СООБЩЕНИЯ-опроса (не версия результатов)
      "Action":   0,                    // ← ОБЯЗАТЕЛЬНО. 0 = отдать голос
      "Choices":  [0]                   // ← массив 0-based ИНДЕКСОВ в Poll.Answers[]
    },
    "LogData": { "YandexUid": "<yuid>", "UserInterface": "<ui>" }
  },
  "Meta": { "Origin": 27 },
  "ClientSupportedFeatures": 1,
  "RequestId": "<uuid>",                          // добавляет транспорт
  "ClientTransportId": { "XivaSubscriptionId": "<hex40>" },  // добавляет транспорт
  "UserAgent": "<ua>"                             // добавляет транспорт
}
```

Ответ:
```jsonc
{ "Status": 1, "MessageInfo": { "TimestampMcs": 1700000000000000 }, "DebugInfo": {…} }
```

### Почему наш `push(Vote{ChatId,Timestamp,Choices,Results})` давал `BACKEND_CALL_ERROR(2)`

Доко-выведенная форма (§11.4) неверна **в двух местах**:

1. **НЕТ поля `Action`** — а оно обязательно (`0` = голосовать). Без него прокси-слой не парсит запрос → `BACKEND_CALL_ERROR(2)` (та же природа ошибки, что у реакции без `Type`).
2. **Есть лишнее поле `Results`** — на исходящем голосе его быть НЕ должно. `Results` — read-only агрегат сервера, в теле голоса он мусор.

Правильное тело `Vote` = **ровно 4 ключа**: `{ChatId, Timestamp, Action, Choices}`. И, как у реакции,
`Vote` идёт **внутри полного конверта `ClientMessage`** (`buildPushParams`: `Meta.Origin`,
`ClientSupportedFeatures`, `LogData`, транспортные `RequestId/ClientTransportId/UserAgent`),
**не плоско** — плоский `push({Vote:{…}})` по аналогии с реакцией даст `NO_SUCH_CHAT`.

### Форма `Choices` — проверено живьём

| действие в UI | `Choices` на проводе |
|---|---|
| одиночный опрос, выбран 1-й вариант | `[0]` |
| множественный опрос, выбраны 1-й и 2-й | `[0,1]` |

`Choices` — **массив 0-based индексов** в `Poll.Answers[]`. Множественный выбор кладёт все выбранные
индексы в один массив за один `push`. Не id, не строки — целочисленные индексы позиции варианта.

### `Action` — что известно

- `Action: 0` — отдать голос. **Наблюдалось живьём**, единственное значение из UI.
- Смена/отзыв голоса: **веб-UI их не предлагает.** После голосования опрос показывает только
  «Посмотреть результаты», кнопки «переголосовать»/«отозвать» нет ни в одиночном, ни во множественном.
  Значения `Action` для REMOVE/REPLACE (по аналогии с Reaction `REMOVE=1/REPLACE=2`) **не подтверждены** —
  из UI недостижимы. Если v2 нужен отзыв голоса — это отдельная проба прямой инъекцией в WS.

## ЧАСТЬ 2 — СОЗДАНИЕ опроса (Priority 2)

Создание = обычное сообщение `push({ ClientMessage:{ Plain:{…, Poll:{…} } } })`. То есть опрос — это
**content-поле `Poll` внутри `Plain`** (§11.1 верна). Все 4 типа отдали `Status:1`.

### Тело `Plain` при создании (структура)

```jsonc
"Plain": {
  "ChatId": "0/0/<chat-uuid>",
  "PayloadId": "<uuid>",                 // client message id
  "CustomPayload": "<base64-json>",       // стандартная web-мета клиента (service/WEB/yuid/ua/version) — НЕ про опрос
  "ForwardedMessageStyles": [],           // пусто
  "IsImportant": false,                   // ← сюда ложится галка «важное» (см. таблицу)
  "Poll": {
    "Title":       "<строка темы>",
    "Answers":     ["<вариант1>", "<вариант2>", …],  // массив СТРОК, минимум 2
    "IsAnonymous": false,                              // ← галка «анонимное»
    "MaxChoices":  1                                   // ← галка «несколько ответов» (см. ниже)
  }
}
```

На создании в `Poll` **нет** `MyChoices` и `Results` — они появляются только на чтении (сервер их заполняет).

### Формы по типам (живьём, `Status:1` у всех)

| тип | `Poll` на проводе |
|---|---|
| одиночный, не-анон | `{Title, Answers:[a,b], IsAnonymous:false, MaxChoices:1}` |
| **множественный** | `{Title, Answers:[a,b], IsAnonymous:false, MaxChoices:2}` |
| **анонимный** (одиночный) | `{Title, Answers:[a,b], IsAnonymous:true,  MaxChoices:1}` |
| анон + множеств. | `{…, IsAnonymous:true, MaxChoices:<N>}` |

🔑 **`MaxChoices` — это и есть кодировка галки «несколько ответов»:**
- одиночный → `MaxChoices = 1`;
- множественный → `MaxChoices = Answers.length` (веб разрешает выбрать все).

Веб-UI даёт только бинарную галку, поэтому живьём `MaxChoices` бывает **ровно `1` или `N`**.
Промежуточные лимиты (напр. «выбери до 2 из 5») провод, вероятно, поддерживает, но UI их не создаёт —
не проверено. Существующий опрос "vote" (4 варианта) имеет `MaxChoices:4` — согласуется.

### ВСЕ галки/поля меню создания «Новый опрос» → wire

Диалог: **Тема опроса** (input) · **Варианты ответов** (≥2 input'а, добавить кнопкой «Добавить вариант») ·
4 переключателя · кнопка «Создать опрос».

| галка/поле в меню (RU) | wire-поле | доказано |
|---|---|---|
| Тема опроса | `Plain.Poll.Title` (string) | ✅ |
| Варианты ответов | `Plain.Poll.Answers` (string[], ≥2) | ✅ |
| **Анонимное голосование** | `Plain.Poll.IsAnonymous = true` | ✅ живьём |
| **Можно выбрать несколько ответов** | `Plain.Poll.MaxChoices = Answers.length` (иначе `1`) | ✅ живьём |
| Отметить как важное | `Plain.IsImportant = true` (сиблинг `Poll`, не внутри него) | ✅ живьём |
| Отправить без звука | **общий флаг сообщения**, не в `Plain.Poll`; по §11.2 — `ClientMessage.NotificationBehaviour`. В теле `Plain` при `SILENT=1` не проявился | ⚠️ не в Poll (общий флаг, отдельно не снят) |

**Других опций у веб-меню нет.** Нет лимита времени, нет «разрешить свой вариант», нет «викторина/
правильный ответ», нет закрытия опроса из меню создания. Ровно: тема + варианты + аноним + множественный
(+ 2 общесообщенческих флага важное/без звука).

## ЧАСТЬ 3 — ЧТЕНИЕ опроса, голоса, кто проголосовал (Priority 3)

### 3.1 Тело опроса из истории/`message_info` (агрегат едет прямо в сообщении)

`ServerMessage.ClientMessage.Plain.Poll` на чтении:

```jsonc
"Poll": {
  "Title": "…", "Answers": ["…"], "MaxChoices": 1,
  "IsAnonymous": true,               // присутствует ТОЛЬКО если true (у не-анон ключа нет)
  "MyChoices": [0],                  // МОИ выбранные индексы (нет ключа, пока я не голосовал)
  "Results": {
    "Version":     1700000000000000, // мкс-версия агрегата
    "VotedCount":  1,                // число РАЗЛИЧНЫХ проголосовавших (не сумма голосов)
    "Answers":     [1, 0, 0, 0],     // счётчики по вариантам, index-aligned к Answers[]
    "RecentVoters":[ {UserInfo} ]    // усечённый список (как RecentUserReactions); НЕТ у анонимных
  }
}
```

- **До первого голоса** `Results = {}` (пустой объект), `MyChoices` — ключа нет. Это и сбило §17.15.
- `Results.Answers[i]` — число голосов за i-й вариант. `VotedCount` — сколько людей голосовало
  (во множественном один человек с `Choices:[0,1]` даёт `Answers:[1,1]`, но `VotedCount:1`).
- `RecentVoters` **усечён** (как reads/reactions) → для полного списка нужен `poll_info`.

### 3.2 `poll_info` — детальный список «кто за что и когда» (не-анонимный)

Запрос:
```jsonc
poll_info { RequestId, ChatId, Timestamp, Limit: 10, ReturnResults: true }   // serviceIndex = 0
```
Ответ (НЕ-анонимный опрос, есть голоса):
```jsonc
{
  "Results": {                        // тот же агрегат, что в теле
    "Version": …, "VotedCount": 1, "Answers": [1,1],
    "RecentVoters": [ {UserInfo} ]
  },
  "MyChoices": [0, 1],                 // мои индексы
  "AnswerVotes": [                     // ← ПОЛНЫЙ разбор «кто голосовал», по одному элементу на вариант с голосами
    { /*AnswerId:0 опущен*/ "TotalCount": 1, "Votes": [ { "Timestamp": 1700000000000000, "UserInfo": {…} } ] },
    { "AnswerId": 1,        "TotalCount": 1, "Votes": [ { "Timestamp": 1700000000000000, "UserInfo": {…} } ] }
  ]
}
```

- `AnswerVotes[]` — **вот где «кто проголосовал»**: элемент на каждый вариант, у которого есть голоса.
  `AnswerId` — 0-based индекс варианта (**опущен, когда `0`**; дальше `1`, `2`, …).
  `Votes[]` = `{Timestamp (мкс, когда проголосовал), UserInfo}`. `TotalCount` — счётчик по варианту.
- `UserInfo` = `{Guid, DisplayName, AvatarId, Version, Uid}` (в чужих чатах ожидаемо шире —
  `PublicName/PhoneId/AccountCategory`, ср. §11.2).
- **Время голоса конкретного пользователя ЕСТЬ** (`Votes[].Timestamp`).
- `Limit` — веб слал `10` (не `50`). Похоже, пагинация голосующих на вариант; для длинных списков
  использовать `AnswerFilter:{AnswerId, MaxTimestamp}` (§14.3) как курсор. Порог обрезки живьём не достигнут (1 голос).
- Пустой опрос (без голосов): `poll_info` отдаёт **ровно `{Results:{}}`** — ни `MyChoices`, ни `AnswerVotes`.

### 3.3 🚨 АНОНИМНЫЙ опрос — голосующие скрыты СЕРВЕРОМ, не только в UI

Проверено на проводе: собственноручно собранный кадр `poll_info` (тот же `ReturnResults:true`)
против анонимного опроса вернул:

```jsonc
{
  "Results": { "Version": …, "VotedCount": 1, "Answers": [1,0] },   // ← НЕТ RecentVoters
  "MyChoices": [0]                                                  // ← свой голос виден
  // ← НЕТ ключа AnswerVotes ВООБЩЕ
}
```

Отличия анонимного от не-анонимного (оба уровня — тело и `poll_info`):

| | не-анонимный | анонимный |
|---|---|---|
| `Results.Answers[]` (счётчики) | есть | **есть** (агрегат виден всегда) |
| `Results.VotedCount` | есть | **есть** |
| `Results.RecentVoters[]` | есть | **ключа НЕТ** |
| `poll_info.AnswerVotes[]` | есть (имена+время) | **ключа НЕТ** |
| `MyChoices` (свой голос) | есть | **есть** |
| UI | аватары + «Посмотреть результаты» | «Опрос анонимный · N голосов», без аватаров, без «Посмотреть результаты» |

**Вывод для v2:** в анонимном опросе узнать, КТО голосовал, **невозможно** — сервер вырезает
`AnswerVotes` и `RecentVoters` даже по явному запросу. Доступны только агрегат (`Answers[]`,
`VotedCount`) и **свой** выбор (`MyChoices`). MCP-клиенту звать `poll_info` для анонимного опроса
за списком голосующих бессмысленно — он вернёт агрегат без людей.

### 3.4 Как отдавать в MCP (предложение)

- **Агрегат** (всегда): `Answers[]` → `{вариант: count}`, `VotedCount`, `MyChoices` → мой выбор.
- **Список голосовавших**: только не-анонимные, из `poll_info.AnswerVotes[]` (имя + время). Для анонимных —
  честно `voters: null / hidden:true`, не выдумывать.
- `poll_info.Limit` — обязательный (ставить явно, напр. 50); ожидать усечение и пагинацию по `AnswerFilter`.
- «Мой выбор» брать из `MyChoices` (есть в теле и в `poll_info`), а не вычислять.

## Поправки в `yandex-messenger-api-research.md`

1. **§11.4 `Vote`**: реальное тело = `{ChatId, Timestamp, Action, Choices:[int]}`. **`Action` обязателен**
   (`0` = голосовать), **`Results` НЕ шлётся**. `Choices` — 0-based индексы в `Answers[]` (массив, множественный = все индексы).
   Уходит внутри полного `ClientMessage`-конверта (`buildPushParams`), не плоско. Ответ `{Status, MessageInfo:{TimestampMcs}}`.
2. **§17.15 — снять/переписать.** `poll_info {…, ReturnResults:true}` возвращает `{Results:{}}` **только у опроса без голосов**.
   При наличии голосов у **не-анонимного** отдаёт `{Results:{…,RecentVoters}, MyChoices:[int], AnswerVotes:[{AnswerId?,TotalCount,Votes:[{Timestamp,UserInfo}]}]}` —
   то есть исходная §14.3 `{answerVotes, myChoices, results}` по сути ВЕРНА. Анонимный — `{Results:{Answers,VotedCount}, MyChoices}` без `AnswerVotes/RecentVoters`.
3. **§14.3 `poll_info`**: `Limit` веб слал `10`; ключ `AnswerVotes` — per-answer (`AnswerId` 0-based, опущен при 0);
   `Results.Answers` — счётчики по вариантам, `VotedCount` — уникальные голосующие. serviceIndex этого метода = `0`.
4. **§11.1 `Poll` (создание)**: живьём тело = `{Title, Answers:[string], IsAnonymous, MaxChoices}` (без `MyChoices/Results` на создании).
   `MaxChoices=1` одиночный / `=Answers.length` множественный. `IsAnonymous` в теле-ЧТЕНИИ присутствует только если `true`.
   Галка «важное» → `Plain.IsImportant` (сиблинг `Poll`), «без звука» → общий `NotificationBehaviour`, не в `Poll`.
5. **§9.3 / голос**: `Vote` — как `Reaction`, полным конвертом; плоский вызов → `NO_SUCH_CHAT` (ложный след).

## Что осталось неясным (честно)

- **`Action` != 0** (отзыв/смена голоса): веб-UI не даёт переголосовать, значения не сняты.
  Нужна прямая WS-инъекция `Vote` с другим `Action`/`Choices` по уже отданному голосу — намеренно не делал
  (лишняя мутация; форма голоса и так закрыта).
- **Порог усечения `RecentVoters` / пагинация `AnswerVotes`**: жил с 1 голосом, обрезка не проявилась.
  `AnswerFilter:{AnswerId,MaxTimestamp}` как курсор — из §14.3, живьём не гонял.
- **Закрытие/удаление опроса, дозакрытие голосования**: в меню создания таких опций нет; отдельный механизм
  (если есть) не искал.
- **`Отправить без звука` → точное wire-поле**: подтверждено лишь, что это НЕ в `Poll` и не в теле `Plain`
  при захвате; по бандлу (§11.2) — `ClientMessage.NotificationBehaviour`, отдельным дампом уровня `ClientMessage` не сверял.
- **`VotedCount` vs сумма `Answers` при нескольких голосующих**: проверено на 1 голосующем
  (во множественном `Answers:[1,1]`, `VotedCount:1`). Правило «VotedCount = уникальные люди» — из этого одного наблюдения.
